## 实施过程中的关键偏差（新对话必读）

- **MySQL 容器端口映射为 `3307:3306`**（开发机 3306 被本机 MySQL 占用）；`application.yml` 默认连 3307，可用 `MYSQL_PORT` 环境变量覆盖。
- **已删除 `MybatisPlusConfig`**：MyBatis-Plus 3.5.9 的分页拦截器拆分到白名单外依赖，且业务不需要分页。
- 本机 Java 是 JDK 21，pom 目标版本 17，编译运行正常。
- 本地开发态：`docker compose up -d` 起库后，`cd hotel-server && mvn spring-boot:run`；前端 `cd hotel-web && npm run dev`。
- admin 预置账号：`admin / admin123`（BCrypt 密文在 data.sql）。
- **库存行预创建（技术方案 v1.2 决策 13）**：启动时 `InventoryPreCreator` 按 `INSERT IGNORE` 预创建未来 730 天库存行；下单事务内绝不建行（实测同事务 INSERT 会引间隙锁/撞键 S 锁两类并发死锁），窗口外日期由 `InventoryRowCreator` 独立小事务懒建兜底。Hikari 连接池已调到 30（REQUIRES_NEW 建行需额外借连接）。
- 集成测试已引入 `hotel-server/src/test`（`mvn test`，需 MySQL 已启动）；并发用例直接用 2099 年日期避免与预创建窗口（今天+730 天）冲突。

## 第二阶段：后端业务（按依赖序）

### T5 auth 模块 ✅（已验收）
- 已实现：注册（手机号格式+唯一性、BCrypt）、登录（共用入口按 role）、登出、me、resolveUser；token UUID 落 auth_token 表（7 天过期）；401/403 拦截。
- 实测通过：TC-A02、A03、A04、A05、A07、A08、A09、A10、TC-H02。

### T6 room 模块（住客侧只读 + 实体/mapper）✅（已验收）
- **目标**：room_type/room 实体与 mapper；`GET /api/room-types`、`GET /api/room-types/{id}`（住客只读，不含剩余量）；`listAssignableRooms(typeId)` 内部方法（在住订单推导空闲，供 T9 用）。本任务不做 admin 维护接口（放 T9）。
- **涉及模块**：room。
- **对应测试用例**：TC-F01①、TC-A01①②。
- **验收条件**：未登录可调两个只读接口返回预置房型；金额以"分"整数输出（元↔分换算只在 DTO 序列化层）。

### T7 inventory 模块（防超卖核心）✅（已验收，库存行预创建见技术方案 v1.2 决策 13）
- **目标**：`InventoryService` 三方法——`queryAvailability`（逐日最小剩余量，无库存行按当前房间数计）、`tryOccupy`（按日期升序原子条件更新，INSERT 撞唯一索引重试一次，失败整单回滚由调用方事务保证）、`release`（逐日 −1 带 >0 保护）。并发集成测试对该接口多线程调用。
- **涉及模块**：inventory。
- **对应测试用例**：TC-G01 库存断言部分、TC-B01/B02 查询语义。
- **验收条件**：N（≥5）线程并发 tryOccupy 同区间，成功数恰为房间数、occupied 永不超 total；queryAvailability 无库存行日期边界正确。

### T8 order 模块（住客侧）
- **目标**：`OrderNoGenerator`（每日序号表、同事务、允许跳号）；创建订单（BR-01 先校验后占用、金额下单时固化 BigDecimal、一个事务内逐日占用+插单）；我的订单/详情（按 token user_id 过滤，忽略前端 userId）；取消（带源状态+user_id 条件更新，成功后 release 库存）。
- **涉及模块**：order（依赖 inventory、room）。
- **对应测试用例**：TC-B03~B13、TC-C01~C05、TC-A06②、TC-H03、TC-G07；并发 TC-G02、G03。
- **验收条件**：非法请求拒绝且不占库存（TC-B13）；中途订满整单回滚无残留（TC-B12）；金额分单位且调价不回溯（TC-B09/B10）；20 线程订单号全局唯一（TC-G07）；越权查/取消被拒（TC-A06②/C05）。

### T9 order 前台侧 + room 维护接口
- **目标**：admin 订单查询（订单号/guest_phone/空查全部）、详情、assignable-rooms；办理入住（BR-06 四项校验、房间行锁+锁内复查+状态条件更新）；办理退房（条件更新+逐日释放）；房型/房间维护（UC-09："新房间数 ≥ 有效订单数"校验、未来库存行 total 同步、改挂双方校验）。
- **涉及模块**：order、room、inventory。
- **对应测试用例**：TC-D01~D09、TC-E01~E05、TC-F03~F08；并发 TC-G04、G05、G06。
- **验收条件**：入住校验文案与原型一致；并发分房仅一笔成功（TC-G04）；提前退房剩余晚数可再售且金额不变（TC-E02/E03）；减房低于有效订单数被拒（TC-F07）；改挂双方库存同步（TC-F08）。
